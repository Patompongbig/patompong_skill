# Portable Codex tool adaptation

Use tools actually exposed in this session; tool names and capabilities vary.
Do not install global settings or change model presets to satisfy this reference.

- Read a selected skill by its exact local manifest path. A generic Skill tool
  or plugin namespace is not required for this file-based installation.
- Use shell/file tools for inspection and edits within authorized scope. Translate
  Bash examples to native PowerShell when needed; do not execute Bash syntax in
  PowerShell. Bundled Bash helpers require Bash and their stated dependencies.
- Use the session's available task/progress mechanism. Keep durable plan ledgers
  in the target project, outside this portable collection.
- Delegate only when the user or selected applicable workflow/skill directs it
  and actual agent tools are available. Follow their current schemas and slot
  limits. Never invent a dispatch or describe self-review as independent review.
- If the selected skill explicitly asks for model routing, use the actual model
  allowlist and supported fork mode. Do not copy version-specific model names or
  configuration advice from old references. Higher-priority routing rules win.
- Bound waits to respect this session's communication requirements. Send useful
  status while work continues; do not copy upstream long-wait recommendations
  when they conflict with the host's required update cadence.
- Detect existing worktree isolation with read-only Git commands. Respect user
  worktree choices and harness-owned workspace lifecycle.
- For merges, pushes, publication, deletion and external messages, follow the
  actual assignment and permission boundaries. Skill installation authorizes
  none of these project-specific side effects.
