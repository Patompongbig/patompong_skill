# Superpowers portable compatibility

All 15 skills are installed as user-selected instructions under `skills/obra/`.
No native plugin, bootstrap hook, global symlink, always-on AGENTS.md, or automatic
updater was installed. The upstream source archive is kept outside the portable
folder. Selection-first routing replaces upstream automatic relevance/startup
rules; named skill references point to this collection's exact manifest paths.

## Optional executables and hosts

All upstream per-skill resources are retained. Bash helpers use Git and standard
Unix utilities; invoke them in Git Bash/another compatible Bash environment, not
PowerShell. A native equivalent must preserve the documented brief, ledger and
diff semantics. JavaScript graph rendering requires Node.js and Graphviz.
The browser companion requires Node.js, Bash and a browser. It writes session
artifacts, starts a local HTTP/WebSocket process, and has cleanup helpers.
Use target-project storage, loopback binding and process-local
`SUPERPOWERS_DISABLE_TELEMETRY=1` when launching. Its upstream remote branding
image can otherwise send a browser request. No server, script, or telemetry ran
as part of this import. The optional logo version lookup may fall back to its
upstream default without plugin metadata; core companion operation is separate.

The validator allows recorded, hash-protected platform literals in four unchanged
upstream scripts: Unix temporary-directory fallbacks and an illustrative Windows
Git Bash path comment. They are not configured personal workspace paths. Real
local links remain checked; missing educational example links are formatted as
inline code rather than presented as bundled resources.

## Delegation and permissions

Agent-driven development, parallel dispatch, independent review, behavioral skill
testing and session diagnosis need actual multi-agent support. Inline execution
has a documented self-review fallback when no reviewer tool exists; disclose that
it is not an independent review. Follow current tool schemas, model allowlists,
wait limits and higher-priority instructions instead of stale host tables.
Installation alone does not authorize delegation for the current maintenance job.

Strong upstream review/approval gates are explained in the catalog. Keep any
existing user authorization; do not ask again solely because the skill's generic
example asks. User-selected TDD applies to suitable implementation work, not
unrelated trivial changes. Never discard existing code to enforce a ritual.
Branch integration, deletion, transcript exports, issue creation and posting are
separate task-specific actions. Session diagnosis reports evidence and preserves
logs; exports require requested scope/redaction review. Project notes, ledgers,
plans and credentials stay outside this portable skill collection.

Static installation checks do not prove native nested discovery, successful
behavioral testing, or Windows runtime execution. Use explicit manifest paths as
the portable fallback and check host discovery in a fresh session. Updates are
manual, on user request, preserving local adaptations.
