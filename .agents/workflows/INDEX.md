# Optional workflow menu

Normal Codex behavior is the default and requires no workflow selection or skill.
Read this menu when the user asks for workflow choices. The full skill catalog is
separate and is opened when the user asks to browse or choose individual skills.

| Workflow | Purpose | File |
| --- | --- | --- |
| ask-answer | Answer and explain through read-only investigation; chat only | [ask-answer.md](ask-answer.md) |
| software-requirement-creation | Create, update or review focused requirements and system context | [software-requirement-creation.md](software-requirement-creation.md) |
| test-and-contract-creation | Define contracts and author/verify tests; Red-only unless minimal code requested | [test-and-contract-creation.md](test-and-contract-creation.md) |
| writing-development-plan | Write, update or review detailed end-to-end feature plans | [writing-development-plan.md](writing-development-plan.md) |
| execute-development | Implement accepted plans through Green tests and iterative QA fixes | [execute-development.md](execute-development.md) |
| feature-and-architect | Maintain deep feature, architecture, function and use-case explanations | [feature-and-architect.md](feature-and-architect.md) |
| interview | Clarify and stress-test an idea | [interview.md](interview.md) |
| lone-skill | Use one named skill and the dependencies it needs | [lone-skill.md](lone-skill.md) |

These are editable starting examples, not automatic task classifiers. Use one
when explicitly selected and preserve that choice until the user changes it.
"Return to normal Codex" clears the selection. The user can name a custom
workflow file directly. See the [optional guide](../WORKFLOW-GUIDE.md).

Create a custom workflow by copying [the template](../templates/workflow.md), or
ask: "Use toolkit-maintain to create workflow <name> combining <skills>."
When adding a workflow, add one concise row here; keep detailed skill descriptions
in the full catalog. This menu does not authorize opening every linked file.
